# Доставка и обслуживание — 0.1.0-alpha.6

Обновление относится к pushok-welcome-bot. Остальные боты имеют собственные версии.
Настройки группы: [WELCOME.md](WELCOME.md). Доступ к этим командам обслуживания получает владелец VPS;
токены для них не нужны. Команды не отправляют сообщений в мессенджеры.

## Что изменилось

1. Ответы Telegram polling сохраняются в SQLite вместе с результатом команды.
2. Ответы VK polling сохраняются таким же образом; тестовый MAX polling тоже использует очередь.
3. После перезапуска ожидающие ответы обрабатываются до нового запроса событий; повтор события не применяет команду снова.
4. `status` показывает состояния очереди отдельно для выбранной платформы.
5. `resolve` позволяет вручную закрыть неподтверждённую попытку без повторной отправки.
6. `/setlimit` задаёт число команд обычного участника за минуту; по умолчанию 20.
7. `/welcomecooldown` задаёт паузу между приветствиями; по умолчанию 30 секунд.
8. `/setup` проверяет правила, FAQ, приветствие и ограничения текущего чата.
9. `prune` убирает старые завершённые ответы, сохраняя ID обработанных событий.
10. Добавлены проверки аварий, обновления, Docker и HTTP; ниже — порядок обновления и приёмки.

## Как устроены состояния

| Статус | Значение | Следующее действие |
|---|---|---|
| `pending` | Ответ записан, попытка отправки ещё не начата | Обработчик отправит после запуска |
| `sending` | Перед обращением к API записано начало попытки | При аварийном перезапуске станет `uncertain` |
| `sent` | Вызов отправки завершился успешно, либо оператор отметил доставку | Автоматически повторяться не будет |
| `uncertain` | Исход неизвестен: сообщение могло дойти | Проверить группу, затем вручную закрыть попытку |
| `cancelled` | Чат удалён из разрешённых либо оператор отменил неподтверждённую попытку | Не отправляется |
| `held` | Ответ удержан после восстановления резервной копии | Не отправляется; см. BACKUP.md |

Запись команды, ID и ответа — одна транзакция. Курсор polling сохраняется после обработки пакета.
Даже если сохранение курсора прервалось, повторно прочитанная команда не изменяет данные ещё раз.
До polling обрабатываются до 50 ожидающих ответов, после сохранения курсора — ещё до 50.
Каждый такой проход прерывается на первой неподтверждённой отправке; оставшиеся ответы сохраняются в pending.
MAX webhook использует ту же процедуру отправки, по одному ответу за проход worker.

Это не гарантия доставки ровно один раз. Любая ошибка вызова отправки сейчас даёт `uncertain`;
автоматического повтора, в том числе после ошибки сети, нет. Возможен сбой между фиксацией `sending`
и фактическим запросом: такой ответ тоже требует разбора. `sent` не подтверждает прочтение человеком.
События, не полученные до истечения срока хранения на стороне платформы, локальная очередь не восстанавливает.
Ответы, потерянные старой версией до обновления, автоматически не появятся.

## Диагностика

Из каталога проекта, пример для обычного Telegram Compose:

```bash
docker compose exec bot python delivery.py --db /app/data/telegram.sqlite3 --platform telegram status --details
```

Для VK замените путь на `/app/data/vk.sqlite3` и платформу на `vk`.
Для MAX webhook:

```bash
docker compose -f compose.max-webhook.yaml exec worker python delivery.py --db /app/data/max.sqlite3 --platform max status --details
```

Используйте фактический `DB_PATH`, если меняли его. Без Docker: `python3 delivery.py --db data/telegram.sqlite3 --platform telegram status --details`.
`status` работает только на существующей базе этого проекта и ничего не меняет. В отчёте — счётчики,
до 100 незавершённых записей с ID события, чатом и статусом. Тексты ответов и токены не выводятся.
Это проверка очереди, а не подтверждение здоровья процесса, HTTPS или реальной доставки.

## Разбор uncertain

Проверьте соответствующую группу. Если ответ виден — отметьте `sent`; если попытку следует закрыть
без подтверждения доставки — `cancelled`. Для нового ответа участник может заново отправить команду;
повтор изменяющей команды создаст новое действие, поэтому сначала проверьте её результат.

Просмотр намерения ничего не меняет. Замените `EVENT_ID` на ID из `status --details`:

```bash
docker compose exec bot python delivery.py --db /app/data/telegram.sqlite3 --platform telegram resolve --event-id 'EVENT_ID' --as sent
```

Для применения остановите обработчик, затем выполните команду в том же томе и возобновите работу:

```bash
docker compose stop bot
docker compose run --rm --no-deps bot python delivery.py --db /app/data/telegram.sqlite3 --platform telegram resolve --event-id 'EVENT_ID' --as sent --apply
docker compose up -d bot
```

Команда принимает только `uncertain`; `pending`, `held` и чужая платформа не меняются.
Для MAX webhook остановите оба сервиса (`docker compose -f compose.max-webhook.yaml stop`),
используйте `run --rm --no-deps worker` с тем же Compose-файлом и затем `up -d`.
Если обработчик ещё держит блокировку базы, применение будет отклонено. Секреты не вставляйте в EVENT_ID.

## Очистка завершённых ответов

Сначала сделайте резервную копию по [BACKUP.md](BACKUP.md). Предварительный просмотр:

```bash
docker compose exec bot python delivery.py --db /app/data/telegram.sqlite3 --platform telegram prune --keep-last 1000
```

Затем остановите обработчик и примените результат:

```bash
docker compose stop bot
docker compose run --rm --no-deps bot python delivery.py --db /app/data/telegram.sqlite3 --platform telegram prune --keep-last 1000 --apply
docker compose up -d bot
```

Остаются последние 1000 **записанных** ответов со статусом `sent`/`cancelled` выбранной платформы.
Порядок определяется записью в очередь, не временем доставки. `--keep-last 0` удаляет все завершённые ответы.
`pending`, `sending`, `uncertain`, `held`, другие платформы, правила, FAQ и согласия не удаляются.
Список ID событий сохраняется, поэтому ранее обработанная команда не исполнится заново после очистки.
Размер файла SQLite может сразу не уменьшиться: освобождённые страницы используются повторно.
Полная очистка ID событий и завершённых webhook-записей пока не реализована; следите за свободным местом.

## Обновление с alpha.5

1. Сделайте копию базы и сохраните `.env`/`groups.json` по BACKUP.md.
2. Остановите процессы. Выполните обновление кода и сборку своего варианта Compose.
3. Проверьте настройки, запустите процессы и подтвердите ответ в тестовой группе.

Обычный Compose, из каталога клонированного репозитория:

```bash
docker compose stop
git pull --ff-only
docker compose build
docker compose run --rm --no-deps bot python main.py check
docker compose up -d
docker compose logs --tail=50 bot
```

MAX webhook:

```bash
docker compose -f compose.max-webhook.yaml stop
git pull --ff-only
docker compose -f compose.max-webhook.yaml build
docker compose -f compose.max-webhook.yaml run --rm --no-deps worker python max_webhook.py check
docker compose -f compose.max-webhook.yaml up -d
docker compose -f compose.max-webhook.yaml logs --tail=50
```

Обновление не требует удаления тома; `down -v` не используйте. Схема таблиц alpha.5 сохраняется,
новые настройки и счётчики хранятся в существующих таблицах. При переходе с alpha.5 MAX-подписку менять не нужно.
При переходе с alpha.4 сначала учтите добавление `user_added`, описанное в WELCOME.md.
Новые ограничения включаются сразу: 20 команд за минуту для участника и 30 секунд между приветствиями.
Администратор может изменить их из чата. Автоприветствие по-прежнему выключено до `/welcomeon`.
Не запускайте alpha.5 поверх новой базы с ожидающей очередью Telegram/VK: старый код её не обслуживает.
Порядок восстановления и риски отката описаны в BACKUP.md.

## Проверка выпуска

- `python3 -m unittest discover -v`: тесты используют синтетические события и временные базы.
- `smoke_container.py`: проверка кода в обоих Docker-образах без сети, от пользователя bot.
- `smoke_http.py`: настоящий Gunicorn с двумя процессами, секрет webhook, перезапуски и повторы; отправка API заменена тестовым объектом.
- На VPS: отправьте `/setup`, настройте FAQ, проверьте ответы обычного участника, перезапуск, `status` и приветствие.
- Для проверки лимита временно поставьте `/setlimit 2`, отправьте четыре команды от обычного участника,
  дождитесь минуты и убедитесь, что команды снова обрабатываются. Затем восстановите нужный лимит.

Реальный VPS и доставка в Telegram/MAX/VK этим выпуском не подтверждены. Меню и мастер добавлены в alpha.7: [MENU_SETUP.md](MENU_SETUP.md). Автоматические резервные копии, повтор заведомо неотправленных запросов и полноценный мониторинг остаются в плане.
