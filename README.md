# Pushok — Помощник новичка

**0.1.0-alpha.7: первый работающий прототип, не законченный продукт.**
Самостоятельный репозиторий, отдельный запуск и база данных. Другие проекты Pushok не нужны.

## Уже реализовано

- Правила с версиями и записью согласия: `/rules`, `/agree`, `/mine`.
- FAQ: страницы `/faq`, ответы `/answer ID`, поиск `/faqfind текст`.
- Управление FAQ из чата: `/faqadd`, `/faqedit`, `/faqdel` — для администраторов.
- Настраиваемое приветствие при вступлении: `/setwelcome`, `/welcomeon`, `/welcomeoff`.
- Состояние и текст приветствия: `/welcome`.
- Русское меню Telegram/MAX/VK и мастер `/wizard`: черновик, проверка, применение и отмена.
- Проверка настройки `/setup`, лимит команд `/setlimit`, пауза приветствий `/welcomecooldown`.
- Постоянная очередь ответов для трёх платформ, диагностика и очистка завершённых ответов.

[Настройка, команды и проверка в тестовой группе](WELCOME.md).
[Очередь, диагностика и обновление с alpha.5](DELIVERY.md).

Команды вводятся латиницей; ответы и инструкции — на русском.

## Платформы и границы

| Платформа | Состояние |
|---|---|
| Локальная демонстрация | Работает без токенов, сценарий проверяется тестами |
| Telegram | Long polling команд и событий добавления участников; реальная доставка не проверена |
| MAX | Webhook с очередью и тестовый Long Polling для групп; реальная доставка не проверена |
| ВКонтакте | Адаптер Bots Long Poll для сообщений; реальная доставка не проверена |
| Каналы / стены сообществ | Публикация пока не реализована |

Автоприветствие по умолчанию выключено; администратор включает его отдельно в каждом чате.
Поддерживаемые события и ограничения каждой платформы перечислены в [WELCOME.md](WELCOME.md).
Меню с кнопками и мастер настройки: [MENU_SETUP.md](MENU_SETUP.md). Административная веб-панель пока не реализована.

## Быстрая локальная проверка

Нужен Python 3.12+ на Linux (включая Ubuntu 24.04). Демо и polling работают без сторонних Python-зависимостей; для webhook используется Gunicorn.

```bash
git clone git@github.com:mrkoster1988/pushok-welcome-bot.git
cd pushok-welcome-bot
python3 -m unittest discover -v
python3 main.py demo
```

Демонстрация хранит данные только до выхода, пользователь `demo` имеет права администратора.
Вводите `/help`, затем команды из списка выше. `/quit` — выход.
Для закрытого репозитория нужен заранее настроенный доступ GitHub по SSH.

## Подключение Telegram

1. Создайте **отдельного** бота через @BotFather. Токен храните только на сервере.
2. Добавьте его в нужный чат. Заполните числовые ID чата и администраторов:

```bash
cp groups.example.json groups.json
cp .env.example .env
chmod 600 .env
chmod 644 groups.json
```

3. В `groups.json` замените `REPLACE_CHAT_ID` и `REPLACE_USER_ID`. Несколько чатов — несколько ключей.
   Роль определяется списком `admins`, а не должностью в мессенджере. Владелец установки управляет этим списком.
4. Запишите токен в `.env` как `TELEGRAM_TOKEN=...`. Не отправляйте файл в GitHub.
5. Если Docker Engine и Compose уже установлены:

```bash
docker compose build
docker compose run --rm bot python main.py check
docker compose up -d
docker compose logs --tail=30 bot
```

Без Docker задайте `TELEGRAM_TOKEN` через окружение и выполните `python3 main.py telegram`.
При таком запуске `.env` автоматически **не читается**.
Если у бота уже есть webhook, процесс остановится, не меняя чужую настройку.
В группе адресуйте команды как `/help@имя_бота`; команды другому боту игнорируются.

## Приёмка и ограничения

- Сначала выполните сценарий из `scenario.json` в тестовом чате. Замените `alice` в административных командах на реальный ID.
- Проверьте отказ обычному участнику в админ-команде, отдельный второй чат, перезапуск с сохранением данных.
- Проверка процесса не подтверждает отправку: убедитесь, что ответы пришли в чат.
- **Локальная SQLite: один polling-процесс или один webhook-worker.** Приёмники webhook используют ту же базу. Блокировка защищает от двух обработчиков на одном сервере.
- Команды и ответы видны всем участникам чата. Внутренняя фильтрация `/mine` не делает ответ приватным.
- Изменение состояния и ID события сохраняются одной транзакцией. Повторное событие не применяет команду снова.
- Ответ сохраняется вместе с командой для Telegram/VK/MAX. Ожидающие ответы переживают перезапуск; неизвестный исход отправки получает `uncertain` без автоматического повтора. Гарантии доставки «ровно один раз» нет.
- Список событий растёт: очистка журнала и полноценный мониторинг — следующие этапы. Резервное копирование добавлено в alpha.4.
- FAQ: до 100 вопросов на чат, по 5 на странице; поиск показывает до 10 совпадений. Ответ FAQ — до 1600 символов.
- По умолчанию обычному участнику доступны 20 команд за минуту. Администраторы освобождены. Приветствия — с паузой 30 секунд на чат. Настройки: WELCOME.md.
- Не рассчитано на массовую нагрузку; нагрузочная приёмка не проведена. Очистка завершённых ответов описана в DELIVERY.md.
