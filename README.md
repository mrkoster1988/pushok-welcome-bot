# Pushok — Помощник новичка

**0.1.0-alpha.2: первый работающий прототип, не законченный продукт.**
Самостоятельный репозиторий, отдельный запуск и база данных. Другие проекты Pushok не нужны.

## Уже реализовано

/rules — правила
/setrules текст — задать правила (админ)
/agree — принять правила
/mine — моё согласие

Команды вводятся латиницей; ответы и инструкции — на русском.

## Платформы и границы

| Платформа | Состояние |
|---|---|
| Локальная демонстрация | Работает без токенов, сценарий проверяется тестами |
| Telegram | Реализован long polling для команд в разрешённых чатах; реальная доставка не проверена |
| MAX | Тестовый Long Polling для групповых чатов; реальная доставка не проверена |
| ВКонтакте | Адаптер Bots Long Poll для сообщений; реальная доставка не проверена |
| Каналы / стены сообществ | Публикация пока не реализована |

Автоприветствие при вступлении и FAQ пока не реализованы.

## Быстрая локальная проверка

Нужен Python 3.12+ на Linux (включая Ubuntu 24.04). Сторонних Python-зависимостей нет.

```bash
git clone git@github.com:mrkoster1988/pushok-welcome-bot.git
cd pushok-welcome-bot
python3 -m unittest discover -v
python3 main.py demo
```

Демонстрация хранит данные только до выхода, пользователь `demo` имеет права администратора.
Вводите `/help`, затем команды из списка выше. `/quit` — выход.
Для закрытого репозитория нужен заранее настроенный доступ GitHub по SSH.

## Подключение Telegram

1. Создайте **отдельного** бота через @BotFather. Токен храните только на сервере.
2. Добавьте его в нужный чат. Заполните числовые ID чата и администраторов:

```bash
cp groups.example.json groups.json
cp .env.example .env
chmod 600 .env
chmod 644 groups.json
```

3. В `groups.json` замените `REPLACE_CHAT_ID` и `REPLACE_USER_ID`. Несколько чатов — несколько ключей.
   Роль определяется списком `admins`, а не должностью в мессенджере. Владелец установки управляет этим списком.
4. Запишите токен в `.env` как `TELEGRAM_TOKEN=...`. Не отправляйте файл в GitHub.
5. Если Docker Engine и Compose уже установлены:

```bash
docker compose build
docker compose run --rm bot python main.py check
docker compose up -d
docker compose logs --tail=30 bot
```

Без Docker задайте `TELEGRAM_TOKEN` через окружение и выполните `python3 main.py telegram`.
При таком запуске `.env` автоматически **не читается**.
Если у бота уже есть webhook, процесс остановится, не меняя чужую настройку.
В группе адресуйте команды как `/help@имя_бота`; команды другому боту игнорируются.

## Приёмка и ограничения

- Сначала выполните сценарий из `scenario.json` в тестовом чате. Замените `alice` в административных командах на реальный ID.
- Проверьте отказ обычному участнику в админ-команде, отдельный второй чат, перезапуск с сохранением данных.
- Проверка процесса не подтверждает отправку: убедитесь, что ответы пришли в чат.
- **Одна копия процесса и локальная SQLite.** Блокировка защищает одну базу на одном сервере.
- Команды и ответы видны всем участникам чата. Внутренняя фильтрация `/mine` не делает ответ приватным.
- Изменение состояния и ID события сохраняются одной транзакцией. Повторное событие не применяет команду снова.
- Если процесс завершится после сохранения команды или отправка не подтвердится, ответ может потеряться. Автоматического повтора ответа нет; это не гарантия доставки «ровно один раз».
- Список событий растёт: очистка журнала, резервное копирование и полноценный мониторинг — следующие этапы.
- Последние 20 записей в списках; длинные ответы ограничены 3500 символами, пагинация пока отсутствует.
- Не рассчитано на массовую нагрузку. Ограничение частоты команд и очередь отправки ещё нужны.

## План развития

1. Проверка Telegram в реальной тестовой группе и доработка профильного сценария.
2. Реальная приёмка MAX и VK; webhook для постоянной работы MAX.
3. Админ-панель, кнопки, наблюдаемость, резервное копирование и установщик.
4. Функции, описанные выше как отсутствующие, и приёмка для каждой платформы отдельно.

Документация транспорта: https://core.telegram.org/bots/api (`getMe`, `getWebhookInfo`, `getUpdates`, `sendMessage`).
Исходный сценарий и проверки находятся в этом репозитории; API-токены не включены.
