# Помощник новичка: FAQ и приветствия — alpha.7

Все настройки относятся только к текущему чату и платформе. FAQ и приветствие другой группы
не изменяются. Управлять ими могут только числовые ID из `admins` в `groups.json`.
Должность администратора в мессенджере сама по себе этих прав не выдаёт.

## Быстрая настройка в тестовой группе

После подключения бота отправьте команды по очереди от администратора из groups.json:

```text
/setrules Уважайте участников. Реклама — только по согласованию.
/faqadd Где посмотреть правила? | Отправьте /rules, затем /agree.
/faqadd Как получить помощь? | Опишите вопрос в группе и дождитесь администратора.
/setwelcome Добро пожаловать! Начните с /rules и /faq. После прочтения правил отправьте /agree.
/welcomeon
/welcome
/setup
```

В Telegram при необходимости адресуйте команды боту: `/faq@имя_бота`,
`/faqadd@имя_бота Вопрос | Ответ`. Команды другому боту игнорируются.
Тексты приветствия и ответов отправляются как обычный текст: HTML, Markdown и подстановка имени не выполняются.

## FAQ для участников

| Команда | Результат |
|---|---|
| `/faq` | Первая страница: до пяти вопросов и подсказка просмотра ответа |
| `/faq 2` | Следующая страница списка |
| `/answer 1` | Полный ответ на вопрос № 1 |
| `/faqfind помощь` | Поиск по вопросам и ответам; регистр и различие е/ё не учитываются |

Поиск показывает до десяти совпадений. Если их больше, уточните запрос.
Это поиск подстроки, без ИИ и без автоматического ответа на каждое сообщение группы.

## Управление FAQ

```text
/faqadd Когда встреча? | По пятницам в 19:00.
/faqedit 1 | Где правила группы? | Правила доступны по команде /rules.
/faqdel 1
```

ID указан в ответе на добавление и в `/faq`. После удаления ID не используется заново.
Удаление убирает вопрос из текущего FAQ; ранее отправленные сообщения бот не удаляет.
Правка FAQ не отменяет согласия участников с правилами. Изменение `/setrules` создаёт новую версию правил,
поэтому участникам нужно снова выполнить `/agree` — это видно по `/mine`.

Лимиты на чат: 100 вопросов, вопрос в одну строку до 180 символов, ответ до 1600 символов.
Ответ может содержать переносы строк и `|`; первый разделитель отделяет вопрос от ответа.

## Автоприветствие

По умолчанию выключено. `/setwelcome текст` меняет текст, `/welcomeon` включает,
`/welcomeoff` отключает, `/welcome` показывает состояние и текущий текст.
Можно включить стандартный текст сразу командой `/welcomeon`. Максимум своего текста — 2000 символов.

| Платформа | Поддерживаемый входящий сигнал |
|---|---|
| Telegram | `message.new_chat_members` в группе/супергруппе; одно приветствие на служебное сообщение, даже если людей несколько |
| MAX | `user_added` с `is_channel=false`, ID пользователя и timestamp; боты игнорируются |
| VK | `message_new` с действием `chat_invite_user` или `chat_invite_user_by_link`, явным положительным `member_id` и ID сообщения беседы |

В VK события без `member_id`, добавление сообщества, личные диалоги и прочие действия пропускаются.
Подписка человека на VK-сообщество и вступление в беседу — разные события: здесь поддерживается беседа.
Telegram-события `chat_member`, вступление через заявку без `new_chat_members` и перечитывание списка
участников не реализованы. Приветствие зависит от того, какие события реально доставляет платформа.
Включение функции не запускает рассылку уже находящимся в группе участникам.

Событие вступления не является текстовой командой и не выдаёт права/не записывает согласие с правилами.
При выключенном приветствии оно учитывается без ответа. Повтор того же события не создаёт второе приветствие;
новый выход и вход с новым ID события может вызвать новое приветствие.
Отключение влияет на последующую обработку событий, но не отзывает ранее сформированные ответы в очереди.

## Лимиты и проверка настройки

`/setup` доступна администратору из groups.json: показывает, что уже настроено и какие команды нужны дальше.
Это проверка сохранённых настроек, а не проверка прав бота в мессенджере или доставки.

```text
/setlimit 20
/welcomecooldown 30
/setup
```

По умолчанию обычный участник может выполнить 20 команд за окно в 60 секунд от первой команды.
При превышении бот один раз сообщает о лимите, затем молчит до следующего окна. Некорректные команды
тоже учитываются; повтор одного события лимит заново не расходует. Администраторы из groups.json
и локальный demo освобождены. `/setlimit 0` отключает лимит, допустимы числа 0–120.
Счётчики переживают перезапуск и изолированы по платформе, чату и участнику.
Один чат хранит до 1000 активных счётчиков; новые участники сверх этого числа временно не получают ответы
на команды, пока не освободится место после истечения окна. Это ограничение памяти, не расчёт на массовую нагрузку.

Между сформированными приветствиями одного чата по умолчанию проходит минимум 30 секунд.
Вступления внутри паузы пропускаются, позже приветствия для них не отправляются.
`/welcomecooldown 0` убирает паузу, допустимы 0–86400 секунд. Сама функция остаётся выключенной до `/welcomeon`.
Лимит команд и приветствия не делят один счётчик. Уже сформированные ответы не отзываются изменением лимитов.
Отсчёт идёт по времени обработки событий на сервере; настройте системные часы.

## Обновление с alpha.4

1. Сделайте копию по [BACKUP.md](BACKUP.md). Сохраните .env, groups.json и текущий DB_PATH.
2. Обновите код, пересоберите и перезапустите свой вариант Compose.
3. В MAX webhook повторите регистрацию **того же URL и секрета**, чтобы добавить `user_added`:

```bash
docker compose -f compose.max-webhook.yaml build
docker compose -f compose.max-webhook.yaml up -d
docker compose -f compose.max-webhook.yaml exec worker python max_webhook.py register --url https://bot.example.org/webhooks/max
```

Замените пример домена на собственный. Команда меняет подписку в MAX, подтверждение описано в
[MAX_WEBHOOK.md](MAX_WEBHOOK.md). Чужой URL автоматически не заменяется.
Один `/welcomeon` без обновления подписки не добавляет событие `user_added` в webhook.

Для Telegram/VK достаточно пересобрать обычный Compose: `docker compose build` и `docker compose up -d`.
Для тестового polling MAX тип `user_added` включён в запросы автоматически после обновления.
Формат базы не меняется, старые данные и очередь команд сохраняются. FAQ/приветствие появятся при настройке.
Если в группу включены сразу несколько ботов для новичков, каждый из них может отправить своё приветствие.

## Приёмка

Локально: `python3 -m unittest discover -v`. Тесты используют синтетические события и блокируют сетевые запросы.
Демонстрация `python3 main.py demo` позволяет настроить FAQ и текст; реального вступления в ней нет.

В настоящей тестовой группе:

1. Настройте правила и два вопроса. Откройте список, ответ и поиск от обычного участника.
2. Убедитесь, что обычному участнику отказано в `/faqadd`, `/faqedit`, `/faqdel`, `/setwelcome`, `/welcomeon`.
3. Включите приветствие и добавьте нового человека. Проверьте фактически пришедшее сообщение.
4. Выключите приветствие и добавьте другого человека. Новое приветствие приходить не должно.
5. Проверьте вторую разрешённую группу: в ней FAQ пуст и автоприветствие выключено до отдельной настройки.
6. Перезапустите бот и убедитесь, что настройки сохранились.

Реальная доставка ещё не подтверждена. Все транспорты сохраняют ответ в очереди; неизвестный исход
отправки остаётся `uncertain` без автоматического повтора. Диагностика и очистка завершённых ответов: DELIVERY.md.
Меню и мастер: [MENU_SETUP.md](MENU_SETUP.md). Полная очистка истории событий и админ-панель пока не реализованы.

Источники схем: [Telegram Message](https://core.telegram.org/bots/api#message),
[MAX Update](https://dev.max.ru/docs-api/objects/Update),
[VK messages schema](https://github.com/VKCOM/vk-api-schema/blob/master/messages/objects.json).
