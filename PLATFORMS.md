# Подключение платформ — 0.1.0-alpha.2

Это тестируемый прототип текстовых команд. Реальные токены и доставка в этом выпуске не проверены.
Сценарий конкретного бота описан в README и scenario.json. Публикация в каналы/на стены,
кнопки, вложения, webhook-сервер и автоматическая модерация пока не добавлены.

## Выбор платформы и чатов

Одна копия процесса обслуживает одну платформу и один бот/сообщество. Каждый проект запускается отдельно.
Для одновременной работы трёх платформ используйте отдельные каталоги установки, файлы .env
и тома базы. Между Telegram, MAX и VK сообщения и участники не синхронизируются.

```bash
cp .env.example .env
cp groups.multi.example.json groups.json
chmod 600 .env
chmod 644 groups.json
```

В .env задайте `BOT_PLATFORM=telegram`, `max` или `vk` и токен выбранной платформы.
В groups.json оставьте раздел нужной платформы и замените примеры на настоящие числовые ID.
Для каждого чата нужен массив admins с ID администраторов. Права внутри бота задаются
этим списком; должность администратора в мессенджере сама по себе их не выдаёт.
Другие чаты игнорируются. Токены в groups.json не записывайте: этот файл читается
пользователем bot внутри Docker (UID 10001), поэтому инструкция даёт ему право чтения.

| Платформа | Секрет и дополнительные настройки | Ключ чата в groups.json |
|---|---|---|
| Telegram | TELEGRAM_TOKEN | chat.id, включая минус для групп |
| MAX | MAX_TOKEN; MAX_CA_FILE при необходимости | recipient.chat_id группового чата |
| VK | VK_TOKEN и VK_GROUP_ID | message.peer_id, для беседы обычно 2000000000 + ID беседы |

ID одного и того же человека в разных платформах различаются. Не копируйте их между разделами.
Старый плоский groups.json из alpha.1 продолжает работать **только с Telegram**.

## Запуск Docker

Нужны заранее установленные Docker Engine и Compose. После заполнения конфигурации:

```bash
docker compose build
docker compose run --rm bot python main.py check
docker compose up -d
docker compose logs --tail=30 bot
```

`check` проверяет синтаксис настроек, числовые ID, наличие токена и обязательных переменных.
Он не подключается к платформам, не отправляет сообщения и не подтверждает действительность токена.
Если проверка не прошла, исправьте указанное поле перед запуском.

Прямой запуск: задайте переменные окружения и выполните `python3 main.py telegram`,
`python3 main.py max` или `python3 main.py vk`. Без явного режима используется BOT_PLATFORM.
При прямом запуске Python файл .env автоматически не читается. Не вводите токены в общий чат.

## Telegram

Создайте отдельного бота через BotFather, добавьте его в тестовую группу.
При включённом privacy mode адресуйте команды `/help@имя_бота`.
Сообщения других ботов и анонимных администраторов игнорируются.
Если уже настроен webhook, запуск остановится; приложение его не удаляет.

## MAX — только тестовый Long Polling

Получите токен на платформе MAX для бизнеса, добавьте бота администратором тестового
группового чата. Используется `GET /updates`, события `message_created`, ответы `POST /messages`.
Личные диалоги, каналы и комментарии этим адаптером пока игнорируются.
При существующей webhook-подписке запуск остановится; подписки не меняются.

По документации MAX Long Polling предназначен для разработки и тестирования;
для постоянной эксплуатации нужен webhook. Его реализация остаётся следующим этапом.
Первый запрос без marker получает только последнее обновление; для проверки отправьте новую
команду после запуска. Далее marker сохраняется в базе после обработки пакета.

На дату проверки документация указывает `https://platform-api2.max.ru` и требования
к доверенным сертификатам. Проверка TLS всегда включена. Если стандартного хранилища
доверия недостаточно, получите сертификат из официального источника и настройте доверие
на своём сервере либо укажите MAX_CA_FILE — путь к доверенному PEM-файлу.
Для Docker дополнительно подключите этот PEM в compose.yaml отдельным read-only томом,
например `./max-ca.pem:/app/max-ca.pem:ro`, и задайте `MAX_CA_FILE=/app/max-ca.pem`.
Программа не скачивает сертификаты и не отключает проверку автоматически.

## ВКонтакте — Bots Long Poll

Используйте отдельное сообщество и **ключ сообщества**, разрешающий работу с сообщениями.
В настройках сообщества включите сообщения, Bots Long Poll и событие `message_new`;
версия используемого API — 5.199. Добавьте сообщество в тестовую беседу с правами,
необходимыми для получения сообщений. Задайте положительный VK_GROUP_ID без `club`.

Работа идёт через groups.getLongPollServer и messages.send. Обрабатываются только события
нужного сообщества от пользователей, исходящие/служебные сообщения пропускаются.
В личном диалоге с сообществом peer_id равен ID пользователя; его тоже надо явно разрешить.
`random_id` ответа стабилен для одного события. При истечении Long Poll ключа он обновляется;
при недоступной истории выводится предупреждение о возможном пропуске событий.

## Обновление alpha.1

1. Остановите старый процесс: `docker compose stop bot`.
2. Сохраните резервную копию базы и конфигурации в защищённом месте.
3. Обновите код. Существующие .env, groups.json и Docker volume не удаляйте.
4. Сохраните прежний `DB_PATH=data/bot.sqlite3` для Telegram, если он уже используется.
   Новый пустой DB_PATH выбирает `data/<платформа>.sqlite3` и не переносит старую базу автоматически.
5. Соберите образ, выполните check и запустите, как описано выше.

Таблица курсоров добавляется автоматически; данные чатов alpha.1 остаются совместимыми.
При первой успешной проверке API база привязывается к ID бота/сообщества для каждой платформы.
Позднейшая смена бота с той же базой блокируется. При первом обновлении с alpha.1 убедитесь,
что используете прежний токен: старый формат не хранил ID бота для сравнения.

## Приёмка в каждой платформе

- Выполнить `python3 -m unittest discover -v` и локальный check.
- Отправить /help в разрешённом тестовом чате и увидеть ответ.
- Пройти команды из scenario.json, заменив alice на ID тестового участника.
- Проверить отказ в админ-команде обычному участнику и игнорирование постороннего чата.
- Перезапустить процесс и убедиться, что данные сохранились, а команды не применились повторно.
- Проверить журналы и записать факт реальной доставки отдельно от успеха локальных тестов.

Позиция чтения хранится после обработки пакета, а ID события — вместе с изменением данных.
При аварии между сохранением команды и отправкой ответ может потеряться. Автоматического
повтора отправки нет. Это не гарантия доставки «ровно один раз». Длительные отключения
могут приводить к потерям из-за срока хранения событий у платформы.
